交互式整合验收：执行前的预期

测试输入由独立的 generate_fixtures.py 生成到 tests/data。正式 app.py 不导入生成器、验收脚本或旧成绩程序。所有案例中的数据和用户确认均为模拟。

| 编号 | 输入与用户选择 | 预期行为 |
| --- | --- | --- |
| 01 | 联系电话/手机号，客户号/编号，联系人/联络人；确认同义和身份依据 | 根据实际电话/编号值交集提出待确认候选；确认映射后按客户编号关联2对，4条输入产出2行；0与001保留 |
| 02 | 总成绩与期末成绩具有相同数值 | 默认保留为不同字段；确认业务编号后只关联记录，两个成绩字段都保留，不执行成绩计算 |
| 03 | 同一文件有两条全部原值完全一致的导出副本 | 未确认不删；确认整行一致代表冗余副本后删除1份，保留被删除记录来源；5条输入−1副本−2关联对=2行 |
| 04 | 同一客户两次服务，不同轮次和值 | 不能按客户号删除；客户号单键出现一对多/多对多，4条记录保留待确认；补充轮次组合键后关联2对，没有去重 |
| 05 | 两个平台同名联系人电话不同 | 仅姓名关联被阻止；改用确认的电话键后没有匹配，两条原记录均保留，不误关联 |
| 06 | 两文件均无学号，外部编号/账户编码及邮箱对应 | 确认映射和外部编号作用域后能关联，保留AC-001及来源 |
| 07 | 同编号城市冲突、另一编号无冲突；另测缺失电话键 | 冲突编号保留双方独立记录与来源，其余继续关联；修改为分别保留两平台城市字段后无需重传即可续算；缺键不按空值相互关联，补充选择已有编号键后续算 |
| 08 | 坏行、未闭合引号、空文件和不支持格式 | 明确报告失败/部分读取和影响行，禁止执行；原始字节保留，不跳过坏行继续交付结果，不生成替代表 |
| 扩展 | GB18030/分号、空格、零值、前导零、多行值 | 记录解码和分隔符修复方式；保持原值；格式转换需单独确认；源物理行号正确 |
| 条件检查 | 只提交confirmed=true，未知字段、无依据或姓名单键 | 即使声称已确认也不能绕过映射、关联与数据检查 |
| 状态 | 保存新方案、开始编辑、旧版本请求、重新加载服务 | 修改使旧结果与下载失效；旧版本请求被拒绝；保存的上传与会话可恢复 |
| 一致性 | API读取报告、页面DOM、CSV下载 | 界面原值和行数与解析结果一致；结果预览与用户下载逐字段一致 |
| 模型 | 未配置模型、模型建议引用未知列 | 明确禁用语义分析；手动闭环可用；无效建议拒绝，不伪造回复 |
