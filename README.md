# 交汇 · 教师数据整合与计分 Agent

把不同平台的 CSV 整理成有来源、可复核的宽表，再按课程规则计算、调整和试算。

交汇是一个**面向教师、在本机运行的最小 Agent**：LLM 理解任务并提出结构化方案，程序检查真实字段、规则和执行条件，再调用确定性 Python 处理数据；遇到缺少依据的情况才向教师提问。未配置模型时，仍可使用有限规则语法和中文表单。

## 它解决什么问题

多平台导出经常存在字段名不同、重复提交、编号缺失、满分不同，以及“未交、缓考、免修”等状态。手工合表容易丢记录，把不同活动误当重复，或在改权重后难以追溯采用了哪份成绩。

交汇将这些决定保存在任务中：教师可以继续补充规则，不必反复上传文件；每项处理均保留原值、文件和原始行位置。

## 可以做什么

- 读取 **2–6 份 CSV，每份不超过 2 MiB**，展示实际表头、原值、读取异常和统计。
- 通过自然语言提出字段、身份关联、活动粒度、重复归并和分制方案；也能展开中文表单修正。
- 根据具体问题生成可选方案，保留自定义答案和继续待确认；不默认替教师选择。
- 支持最高分、按有效提交时间取最后一次、平均、累加、仅接受一致值等归并方式。
- 支持自定义考核项目：直接采用、平均、最高分、最佳 N 项、内部加权和封顶等受限计算。
- 计算总评、保留特殊状态、对指定编号或固定条件范围做有依据的局部调整。
- 保留历史任务、问题草稿、独立试算、调整前后差异、CSV 下载和中文 TXT 处理明细。

**没有提到计算时，先完成数据整理；之后可以在同一任务中追加计分要求。**

## 为什么采用这个结构

这里的特点是让每一步可核对，不是让模型直接“算出答案”：

1. **数据治理与业务计算分离。** 阶段一独立保存宽表，阶段二以它为输入。仅修改权重可复用宽表；数据整理改变时相关旧计算失效。
2. **理解与执行分离。** 模型提出方案；Python 检查字段、分制、权重合计、公式依赖、适用范围和版本后执行。模型不能用“已确认”绕过人工裁决。
3. **不把信息缺失当作业务规则。** 0 是有效值，空值不补 0；样本最大值不代表满分；缺时间不按行序猜“最后一次”；同名不代表同一对象。
4. **原值与来源保留。** 归并后的记录仍可追溯被折叠的提交，冲突不会静默选一个值。
5. **教师可以继续任务。** 已明确的决定跨阶段沿用，追加指令必须进入实际执行请求；试算不直接覆盖已采用结果。

这是领域受限、由程序控制工具的 Agent，不是任意文件解析器，也不宣称能可靠理解任意自然语言或优于所有通用 Agent。

## 快速开始：Windows

### 1. 准备环境

- Windows 10/11，安装 **Python 3.11 或以上**，安装时包含 Tcl/Tk，并勾选 Add Python to PATH。
- 下载仓库 ZIP 并解压，或用 Git 克隆到普通可写目录；不要直接在 ZIP 中运行。
- 正式使用**不需要 pip 安装依赖，不需要 Node、Playwright、VS Code**。

### 2. 双击启动

双击项目根目录的 **启动控制台.vbs**。如果系统禁用了 VBS，双击 **启动控制台.cmd**。

在控制台中：

1. 无模型也可以先点击“启动服务”。
2. 健康检查通过后，点击“打开教师页面”。
3. 首先使用 [01 基础计分案例](examples/01_基础计分_无需模型)，验证上传、计算和下载。
4. 配置模型后，体验自然语言理解和动态问题选项。

命令行入口仍可用：

    python -B -X utf8 tools/launch.py --check-only
    python -B -u -X utf8 tools/launch.py
    python -B -u -X utf8 tools/launch.py --no-browser --port 8767

默认页面为 http://127.0.0.1:8765/pipeline；首页 / 提供通用两 CSV 整合工作台。端口占用时在控制台换端口，不会自动结束其他服务。

### 3. 配置真实模型

支持非流式 **Chat Completions 兼容接口**，包括已有 DeepSeek 配置入口。不同服务的兼容程度需实际验证。

推荐在本机控制台填写：

- 完整接口地址，例如服务商提供的 /chat/completions 地址；
- 该账号实际可用的模型名称；
- 遮蔽输入框中的 API 密钥。

普通配置保存到 config/model_config.local.json。默认“仅本次使用”不保存密钥；只有明确选择“在本机记住密钥”，才写入 config/secrets.local.json，**这是明文文件，没有加密**。

也可从 model_config.example.json 复制普通配置，密钥通过服务端环境变量 INTEGRATION_MODEL_API_KEY 提供。命令行方式优先环境变量，再回退本机密钥文件；控制台以使用者明确选择的来源为准。更改运行中的配置后需要重启服务。

网页不接收密钥，不将密钥保存到浏览器。不要把本机配置、密钥或运行状态上传到 GitHub。

“检查模型连接”只验证连接和 JSON 协议，不代表真实任务理解已通过。外部 API 可能超时、限流或返回非法方案；此时保留任务和答案，页面可重试或使用中文表单，不会把故障显示为计算成功。

任务描述、真实表头和统计会发送给配置的模型服务；只有启用 allow_sample_values 才发送每表最多 3 条样例。请根据学校要求决定是否使用外部模型。

## 教师如何使用

1. **新建任务**，在底部输入要求并选择同一案例或同一课程的 CSV。
2. 查看理解摘要。文件和表格通过右侧任务文件或查看器打开，不必在主对话中浏览整张表。
3. 有问题时，在输入栏上方的卡片选择方案、填写必要参数，或选择“自定义处理方案”补充。
4. 清洗完成后可下载阶段一宽表；要求计算且规则完整时自动继续阶段二。
5. 需要改规则，在同一输入框追加；需要试算可写“看看变化”，核对差异后再决定是否采用。
6. 下载当前结果 CSV 和中文 TXT 处理明细，核对原值、规则、来源及异常。

例：

> 以主名册为主表，按编号关联。实验是同一活动的重复提交，取最高分；作业按有效提交时间取最后一次。实验占40%，作业占60%，未交记0，缓考保留，保留一位小数。

已知事项应明确写出；缺少依据时系统追问。不要为了继续执行而随意填成绩、满分或身份。

“关闭项目页面”“停止服务”“退出控制台”是独立动作。停止服务不会清空数据。历史任务保存在状态目录，刷新可恢复；“新建任务”不会删除旧上传和审计。

## 能力边界与常见问题

- 当前只支持 CSV；XLSX、PDF、平台 API、多人账号和公网部署未实现。
- 默认仅监听本机。另一台电脑应独立下载、配置和运行，不等于远程访问本机服务。
- 缺时间、冲突值、身份歧义、缺计分依据可能阻断执行，必须依据真实记录补充。
- 模型输出会被拒绝；重试不代表已经成功。复杂业务未覆盖时使用表单或保留待处理，不应跳过校验。
- 双击没有窗口：确认 Python 版本、Tcl/Tk、目录写权限，或用启动控制台.cmd查看错误。
- 端口被占用：在控制台换端口；本项目不会接管已有服务。
- 想从空白开始：点“新建任务”，无需删除状态目录。

## 开发与验收

可先运行 python -B -X utf8 tools/verify_demo.py 进行无模型的独立HTTP冒烟检查；它不使用用户历史任务。

正式运行只依赖 Python 标准库。Windows 桌面控制台使用标准库 Tkinter；浏览器验收使用的 Node/Playwright仅是开发工具。

本机开发测试源码与历史产物位于独立 support 目录，不是运行依赖。[发布验收说明](docs/release_validation.md) 记录本次实际检查、真实模型验收、失败与限制，并提供可独立运行的公开冒烟检查。不要把连接测试或离线fixture当作模型任务成功。
