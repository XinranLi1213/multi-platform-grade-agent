# 自然语言任务与可选计分

教师在工作区底部描述任务、选择CSV并点击“开始处理”。灰色提示建议说明用途、关联与归并方式；需要计分时再说明项目、规则。普通页面不要求使用JSON。

只说“整理文件”时，工作流只完成数据层。有歧义只询问影响整理的具体内容；没有问题则保存阶段一宽表，状态为“数据整理已完成”。计分区保留为折叠的可选功能，不追问权重、不生成总分。

上传后输入区显示已保存文件数量，隐藏重复上传入口，使用“发送补充并继续”。补充问题和追加计分都复用同一任务及上传。新一批文件请从左侧新建任务。需要时，用户也可从可选计分表单明确发起计算。

之后说“现在计算总评”时，才检查计分依据。缺少权重或公式则具体提问；已明确的项目、特殊状态、精度和权重保留，不要求再确认。完整规则通过程序校验后自动计算。只有阶段二改变时复用阶段一宽表，整理方案改变则让依赖结果失效。

例如先说“先只整理，未交记0，保留一位小数”：阶段一仍保留“未交”原值，记0与精度作为后续事实保存。之后再补“实验40%，作业60%”，程序直接采用之前明确的政策，不再追问一次。明确要求暂不计算时，不因保存了将来的规则而立即计分。

## Agent 分工与边界

1. Python实际读取CSV，给模型真实表头、统计、候选键缺失/重复，以及按当前主表实际比较得到的编号匹配、姓名与班级冲突计数。默认不发送原始编号或姓名，样例仍受原配置控制。
2. 真实配置的模型理解任务与上下文，提出数据/业务方案和具体问题，不计算学生成绩、不声称已经替教师确认。
3. Python检查字段、归并枚举、项目来源、分制、公式、人工决定、指令引用与版本。程序拒绝无依据猜权重和违反“保持整理方式不变”的方案。
4. 可修正的模型结构或遗漏引用最多反馈修正一次；伪造身份裁决等直接拒绝。仍失败则明确说明可重试或手动处理，上传不丢失。
5. 合法方案由现有确定性Python执行并检查产物；缺项在同一输入框补充，模型读取已保存文件与决定继续。阶段一独立持久化，阶段二可选。

这是有界任务工作流，不是无限自主运行或任意代码执行平台。未配置模型时，只支持说明过的有限语法及中文表单；不使用模拟回复。简短指令有时可以直接整理，有时仍需合理澄清；真实模型质量不能保证每次相同。

界面在请求期间显示正在处理，按钮防重复。响应读取受配置时限约束，网络超时或模型方案失败会就地解释并保留草稿和上传；不能把失败显示成执行成功。

相关实现：`pipeline/intent.py`控制执行范围；`pipeline/advisor.py`提供真实模型方案及有界修正；`pipeline/semantic.py`提供实际数据证据；`pipeline/service.py`保留流程、事实和执行状态；`integration/model_client.py`负责受控传输；原双阶段计算和审计继续沿用。

程序更新涉及后端，需要在项目控制台停止再启动服务，然后刷新页面。历史任务和API配置保留；原来的待处理任务可以直接重试理解或补充，不必重传。
