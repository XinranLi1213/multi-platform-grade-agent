# 0.3.1-preview 补丁验收

日期：2026-10-24。本补丁保留0.3.0-preview，不修改历史发布资产或用户状态。

## 修复范围

- 整理说明与计算说明使用不同的HTML编号，仍下载中文TXT。
- 模型超时、连接失败与方案校验失败分别显示；问题状态保留错误代码与理解尝试次数。
- 操作超过15秒时显示真实已等待时间，不用虚假的百分比进度，不改变执行状态。
- 网络超时或连接失败时，最多重试一次理解请求，使用完全相同的上下文；不把网络错误作为新的教师指令或方案修复依据。认证、权限及限流错误不自动重试。
- “重试理解”只重试最后一次已提交指令。输入框的未提交草稿保留，只有点击发送才进入执行请求。
- 保留程序字段/分制/规则校验、流程版本与重复请求保护；没有增加自动补分或跳过确认的路径。

## 验收方式

### 确定性检查与故障注入

维护环境的6项新增离线契约检查覆盖：相同上下文重试、连续两次超时停止、认证/权限/限流不自动重试、失败后数据保留与请求幂等、不同表达的计算意图边界、虚构字段与伪造身份确认拒绝。离线替身明确标记，不算真实模型成功。

真实Edge页面的故障注入模拟前两次理解超时：15秒后显示等待时间；页面显示“模型响应超时”；在输入框填写尚未提交的新规则后，点击重试仍只发送原指令；双击不重复提交，计算86.0/54.0/32.0。两次自动理解请求上下文相同，教师重试后的第三次成功；实际CSV和TXT按钮可下载，未提交草稿保留。

维护命令（测试源码在项目外，不是教师运行依赖）：

    python -B -X utf8 <support>/development/tests/test_patch_contracts.py
    python -B -X utf8 <support>/development/tests/test_release_contracts.py
    python -B -X utf8 <support>/dev.py test all
    python -B -X utf8 <support>/dev.py browser conversation
    python -B -X utf8 <support>/dev.py browser ui-options

公开包可直接运行：

    python -B -X utf8 tools/verify_demo.py

### 真实模型的任务检查

使用服务端已有真实模型配置、隔离状态及真实浏览器按钮，不预填模型方案，不改后台状态；按[自然语言表达验收](../examples/自然语言表达验收.md)的6类任务核对。连接检查与任务理解验收分开。原始数据全部为随包合成CSV，不使用真实用户上传。

模型修复/重试次数保存在任务建议及审计中，不声称模型每次首个响应都正确。

- 原有Python回归140/140通过；原发布契约7/7通过；新增补丁契约6/6通过。旧CLI另24/24通过。
- 原有真实浏览器19组通过，含40人完整流程、身份/时间异常续算、版本冲突、两阶段失效与复用、草稿及下载。
- 新增超时注入浏览器场景通过，含等待提示、错误分类、未提交草稿保护、双击防护、不同说明链接及实际下载。
- 真实模型6类任务全部通过：中文四成/六成得到86.0/54.0/32.0；各占一半得到85.0/45.0/40.0；不同展示得到50.0/90.0/10.0；只整理不生成总评；未知满分先追问，补50后得到40/0/80，再追加计算得到40.0/0.0/80.0并复用阶段一；缺权重时仅追问权重，补充后得到86.0/54.0/32.0。

这些结果仅针对上述输入、配置的真实服务和本轮执行；不能承诺外部API从此不再超时或其他表述必然成功。

## 环境与边界

本轮维护者测试在同一台Windows电脑进行，使用独立状态。使用者已反馈完成自行实测，但未提供另一台电脑的系统、Python版本及逐项记录，故不推断其环境。其他电脑可按上面的公开冒烟和案例步骤记录自己的结果。

有限测试无法证明任意自然语言均正确。验收目标是：支持范围内有依据地执行；关键条件不足时只询问缺项；模型失败时暂停、保留数据，并允许重试或手动流程。外部API仍可能超时、限流或理解错误。

双阶段计分引擎文件未改动。没有迁移、替换历史路径或修改旧哈希；跨电脑历史状态仍按README的归档与重跑方式处理。正式服务未被接管或停止，密钥不进入提交和分发包。
